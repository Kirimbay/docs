# Звери на сервере Hiddify — простая инструкция

На сервере появляются 4 новых подключения («звери»). Они работают рядом с Hiddify и сами
добавляются в подписку каждого пользователя. Ссылки пользователей не меняются.

| Зверь | Порт | Что это |
|---|---|---|
| 🦉 Сова | 2053 (TCP) | VLESS gRPC |
| 🐅 Тигр | 8444 (TCP) | VLESS Reality |
| 🦆 Утка | 2083 (TCP) | VMess |
| 🐟 Рыба | 36099 (UDP) | Hysteria2 |

## 1. DNS (Cloudflare, зона kirz.co.uk) — сделать первым
Создай A-запись `x<N>.kirz.co.uk` (N — номер сервера, например `x20`), облако **серое** (DNS only).
- Сервер без relay: IP = IP сервера.
- Сервер за relay: IP = **IP relay**. Relay должен пересылать на сервер **все порты, кроме 22**
  (TCP и UDP). Тогда все звери работают через relay, ничего отдельно настраивать не надо.
Подожди 1–2 минуты: `ping x<N>.kirz.co.uk` должен показать этот IP.

## 2. Установка — одна команда (на сервере, под root)

    curl -fsSL https://ro1.kirz.co.uk:8090/get.sh | bash -s -- --domain x<N>.kirz.co.uk

Это ставит 4 зверей (Сова, Тигр, Утка, Рыба) на стандартные порты. Если нужно иначе:
- выбрать зверей: `--animals сова,тигр,рыба`
- свои порты (по одному на каждого выбранного зверя, по порядку Сова,Тигр,Утка,Рыба): `--ports 2053,8444,2083,36099`
- 🦀 Краб (Trojan, порт 2097) по умолчанию **не ставится** (у тестеров не работал). Включить вручную:
  `--animals сова,тигр,краб,утка,рыба` (порты тогда: `--ports 2053,8444,2097,2083,36099`)

Скрипт сам делает бэкап, ставит, проверяет подписки (все пути, разные приложения, несколько
реальных пользователей). Если что-то не так — сам всё откатывает. В конце: `VERIFY PASS` и `SUMMARY`.
Старые конфиги Hiddify остаются включены. Повторный запуск безопасен.

## 3. Убрать (или вернуть) зверя
Запусти ту же команду, перечислив только нужных зверей. Например, убрать Утку:

    curl -fsSL https://ro1.kirz.co.uk:8090/get.sh | bash -s -- --domain x<N>.kirz.co.uk --animals сова,тигр,рыба

Убранный зверь пропадает целиком: порт закрыт, правило файрвола удалено, из подписок исчез.
Вернуть — снова запустить без `--animals` (стандартные 4 зверя).
Если на сервере раньше стоял Краб — обычный повторный запуск без `--animals` его уберёт (порт 2097 закроется).

## 4. Выключить старые конфиги Hiddify (по желанию, отдельно)

    bash /etc/tmpl/disable-old.sh

После этого в подписке остаются **только** звери. Скрипт делает бэкап и проверяет, что старых
серверов в подписке нет; если проверка не прошла, сам всё возвращает. Включить обратно:
`bash /etc/tmpl/disable-old.sh --undo`

## 5. Проверка в Happ
Happ → подписка → «Обновить». Должны появиться 🦉 Сова, 🐅 Тигр, 🦆 Утка, 🐟 Рыба (Краба нет).
Подключись к каждому — сайты открываются. Подписка не должна быть пустой (ни по новой, ни по старой ссылке).

## 6. Новый сервер из бэкапа Hiddify (переезд)
1. Поставь Hiddify 12.0 на новый сервер.
2. В панели: Резервная копия → Восстановить → загрузи бэкап старого сервера и **обязательно включи
   восстановление настроек**, а не только пользователей.
   Почему: ссылки подписок зависят от двух путей в настройках — `proxy_path_client` и скрытого
   старого `proxy_path`. Если восстановить только пользователей, пути будут новые и **все старые
   ссылки перестанут работать**. UUID пользователей сохраняются из бэкапа.
3. Перенеси DNS (`x<N>` и домены подписок) на новый сервер/relay.
4. Запусти команду из п.2. В начале она печатает `SUBSCRIPTION PATHS: ...` — сравни оба пути со
   старым сервером. Если какой-то путь `EMPTY` или другой — остановись и восстанови настройки.
5. Если на старом сервере в haproxy был свой «переходник» для старых ссылок (ручные правила в
   `/opt/hiddify-manager/haproxy/haproxy.cfg` вне блоков `# BEGIN tmpl-sub`), чистая установка Hiddify
   его не перенесёт: скопируй эти строки со старого сервера в то же место и сделай Apply.
   (На серверах 8 и 20 такого переходника нет — проверено.)

### 6b. Нода на 12.3.x → откат к схеме 12.0.0 (под tmpl)

На 12.3.3 tmpl verify (HiddifyNext JSON) может не пройти. Надёжный путь — как в памятке:
чистая ОС → Hiddify **12.0.0** → restore бэкапа → фикс `extra_params` → потом `get.sh`.

Скрипт (ОС сам не переустанавливает):

```bash
# на старой 12.3.x:
bash /root/tmpl-install/prepare-12.0-from-backup.sh export
# скопируйте /root/hiddify-migrate-* офсайт, переустановите Ubuntu 22.04, верните каталог в /root/

# на новой ОС:
bash /root/hiddify-migrate-XXXX/prepare-12.0-from-backup.sh after-os /root/hiddify-migrate-XXXX
# затем tmpl:
curl -fsSL https://ro1.kirz.co.uk:8090/get.sh | bash -s -- --domain xN.kirz.co.uk
```

Если restore уже сделали руками в UI и панель «кривая» — только фикс:

```bash
bash prepare-12.0-from-backup.sh fix-only
```

⚠️ В UI Restore **не нажимайте второй раз**.

## 7. Откат — одна команда

    bash /etc/tmpl/rollback.sh

Убирает зверей и возвращает сервер к состоянию до последней установки (бэкапы в `/root/backup-tmpl-install-*`).

## 7. Relay (промежуточный сервер) — одна команда
Relay — это отдельный простой сервер, который пересылает всё на основной сервер со зверями
(«exit»). Hiddify на relay ставить **не нужно**. На relay под root:

    curl -fsSL https://ro1.kirz.co.uk:8090/get.sh | bash -s -- --relay --exit IP_ОСНОВНОГО_СЕРВЕРА

Что делает: включает пересылку пакетов (навсегда, переживает перезагрузку), пересылает на exit
**все TCP-порты, кроме 22** (чтобы SSH на сам relay работал) и **все UDP**. Правила сохраняются
(ставит iptables-persistent). Повторный запуск безопасен — старые правила заменяются новыми.
Исключение — **UDP 443 не пересылается**, а отклоняется (HTTP/3 выключен): МТС на LTE режет UDP 443,
и Happ, запомнивший HTTP/3, ждал до таймаута подписки. Остальные UDP (24328, 24329, 36099) и весь TCP работают как прежде.
- оставить на relay ещё порты (не пересылать): `--keep 22,8090`
- убрать relay полностью: `curl -fsSL https://ro1.kirz.co.uk:8090/get.sh | bash -s -- --relay --remove`

Потом в DNS запись `x<N>.kirz.co.uk` должна указывать на **IP relay** (см. п. 1).

## HTTP/3 (Alt-Svc) выключен
Hiddify объявлял `Alt-Svc: h3=":443"`, Happ это запоминал и ходил за подпиской по UDP 443, а МТС на LTE
его режет — подписка не обновлялась. Теперь установщик (hap-ins.py) убирает h3 из haproxy и из шаблонов
Hiddify (копии `*.bak-h3`, так что обновление панели его не вернёт) и отдаёт `Alt-Svc: clear` на всё.
verify.py проверяет, что h3 нигде не объявлен; rollback.sh всё возвращает. Если у клиента Happ всё ещё
таймаут — переустановить подписку или перезапустить Happ (сбросить запомненный h3).

## 8. Фикс после инцидента x60 (на уже установленных серверах)

На каждом EXIT (Hiddify+tmpl), под root:

    bash /root/tmpl-install/fix-all.sh
    # вход в админку только по UUID-ссылке без пароля:
    bash /root/tmpl-install/fix-all.sh --clear-owner-password

На каждом RELAY:

    bash /root/tmpl-install/fix-all.sh --relay
    # или: bash /root/tmpl-install/fix-all.sh --relay --exit IP_EXIT

Чинит: admin_path вне ACL tmpl-sub; cert домена в haproxy ssl; retries/таймауты sub; UDP/443 на relay REJECT (быстрый отказ → TCP для Happ на LTE).

Админка (пароль Owner пустой):

    https://<домен>/<proxy_path_admin>/<owner_uuid>/

Скрипт лежит также: /root/tmpl-fix-all.sh
Исходники инсталлера в /root/tmpl-install/ уже пропатчены — перед публикацией нового get.sh/tgz пересоберите dist с этой папки.

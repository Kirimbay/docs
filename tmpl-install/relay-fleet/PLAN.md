# План: пул релеев + авто DNS-failover

Дата: 2026-10-28 (Europe/Moscow). Парк: exit Hostup `136.148.*` + фронты SERV.HOST.

## Роли людей и автоматики

| Кто | Что делает |
|-----|------------|
| **Вы** | Покупаете IP/VPS на SERV.HOST; кидаете IP агенту; по алерту «пул пуст» — докупаете |
| **Скрипт** | Пробы `релей→exit`; если primary плох и backup жив — **сам** меняет A в Cloudflare; алерт в Telegram/лог |
| **Агент/ИИ** | Заводит DNAT на новом IP (`relay.sh --exit …`), дописывает inventory, не покупает IP сам |

**Авто-flip DNS — да. Покупка IP — нет (только вы).**

## Целевая схема (норма)

```
клиент → [SERV.HOST front IP] → iptables DNAT+MASQ → [Hostup exit]
```

На каждый exit: **1 primary + ≥1 backup** на **разных машинах** и по возможности разных префиксах (`2.26` / `144.31` / `80.66`).  
TTL DNS 60. Ссылки пользователям не переиздавать.

## Автоматика

1. `probe_and_failover.py` по timer (1–2 мин) или cron.
2. Проба с **машины фронта** (SSH): TCP 443 (и опционально 2053) до exit, N попыток.
3. Primary `< threshold`, backup `>= threshold` → CF update всех `domains` exit’а на backup IP; `current` в state-файле.
4. Алерт: flip / пул без живых backup / путь восстановился (без авто-failback по умолчанию).

Failback на старый primary — **ручной** или отдельный флаг (чтобы не флапать).

# Шесть выходов за одним SNI relay

Живой контракт на 2026-11-07. Это не схема `relay.sh` (один DNAT на один exit).
Старый план в ветке `cursor/relay-fleet-failover-b18a` для этого входа не канон:
там другие IP и запрет HAProxy. Здесь HAProxy — согласованный вход именно для
этих шести выходов.

## Сброс неудачного рукопожатия

Живой вход сейчас `136.148.213.105`. Конфиг HAProxy не менялся: неполный
ClientHello ждётся до 1 с, неизвестное имя никуда не отправляется, 70-й сервер
на этот вход не входит.

Отказ раньше закрывался обычным FIN, и приложение могло держать попытку.
Процесс HAProxy теперь загружает `/usr/local/lib/relay-rst-reject.so`
(`tmpl-install/relay-sni/relay-rst-reject.c`). Сокет порта 443, с которого ещё
не ушло 400 байт ответа, обрывается RST. Сессия, где сертификат или страница
уже ушли, закрывается как прежде. Порт 80 модуль не трогает.

Откат на фронте, без правки DNS и выходов. Перезапускает HAProxy, текущие
туннели переподключаются:

```bash
/root/relay-reject-rst-rollback.sh
```

## Контракт

- Вход: `130.78.25.124`, HAProxy 2.4, TCP 443, SNI passthrough.
- Нет TLS termination и нет PROXY protocol.
- Нет backend по умолчанию. Неизвестное или пустое SNI закрывается.
  Нельзя отправлять unknown SNI на один из шести выходов.
- Backend только по IP, никогда по имени `xN`, иначе петля после DNS.
- Имена на этот IP: `x12/x15/x36/x51/x57/x60.kirz.co.uk`,
  `12/15/36/51/57/60.kirvpn.ru`, те же на `kirvpn.us`, и `60.sarafan.uk`.
- Выходы: `12=136.148.216.221`, `15=136.148.216.46`, `36=136.148.220.250`,
  `51=136.148.220.248`, `57=136.148.216.157`, `60=136.148.216.164`.
- Порт 80: HTTP Host на тот же выход (ACME). Неизвестный Host — 403.
- Не менять: UUID, ключи, shortId, SNI, flow, fingerprint, порты и подписки
  на выходах; DNS кроме уже переключённых 19 имён; `217.60.183.221`, IPv6 и
  MTU 1400 без отдельного подтверждения.

## Что уже проверено снаружи и чего это не доказывает

Полный ClientHello с этой диагностической сети доходит: 19 имён отдают свой
сертификат и то же тело главной страницы, что и прямой заход на exit.
Неизвестный SNI на relay сертификат не получает. Это не проверка Reality и не
проверка сети пользователя.

TCP SYN до `130.78.25.124:443` с диагностической VM отвечает локальный
посредник (RTT рукопожатия доли миллисекунды, MSS 1460, TTL 127). ICMP до
того же IP идёт по настоящей сети (~100 мс) и проходит на 1400 байт, но не
на 1408. Поэтому MSS и таймер неполного ClientHello, снятые с этой VM,
нельзя считать настройкой HAProxy. На самом relay прежний захват видел FIN
через ~5 с; локальный посредник закрывает неполный hello через 1 с и эту
цифру надо отбрасывать.

Пробный `bind mss 1200` уже откатили: источник, который присылал один сегмент,
стал присылать один сегмент нового размера. Это не чинит односегментные потоки
и не было привязано к пользователю. Повторять без его запроса не нужно.

## Следующий шаг, когда есть SSH

Ключ диагностики добавляется в `root@130.78.25.124` отдельно. До этого
конфиг не менять.

1. Пользователь один раз обновляет подписку 15-го сервера без VPN и пишет «нажал».
2. В эту минуту смотреть journal HAProxy по публичному SNI
   `15.kirvpn.ru`, `15.kirvpn.us`, `x15.kirz.co.uk`.
3. Если такого соединения нет — обрыв до relay. HAProxy не переписывать.
4. Если SNI есть и backend выбран — сравнить завершение с логом exit 15.
5. Если SNI пустой — не назначать выход по умолчанию.
6. Захват только заголовков (`snaplen` 54) и только по найденному соединению.
   Сырой файл удалить после сводки. Payload не сохранять.

## Откат

- Полный конфиг входа: `/root/relay-backup-20261107/rollback.sh`
- Откат только диагностического лога SNI: файл
  `/root/relay-fix-diag-20261107-1225/haproxy.cfg.before`, затем
  `haproxy -c -f /etc/haproxy/haproxy.cfg && systemctl reload haproxy`
- DNS: бэкап не в этом репозитории. Откат 19 A-записей только после
  отдельного согласия.

## Проба

```bash
python3 tmpl-install/relay-sni/probe_public.py
```

Код 0 — публичные проверки прошли и SYN не был локальным. Код 2 — те же
проверки прошли, но SYN локальный: для вывода о пользователе этого мало.
Код 1 — расхождение DNS, сертификата, тела страницы, unknown SNI или порта 80.

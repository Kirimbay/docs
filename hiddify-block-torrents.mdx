## Что выполнить на сервере

Под root, по SSH, на каждой машине с Hiddify Manager. Пока PR не в `main`, берите файл **с ветки** и проверяйте версию **до** запуска:

```bash
curl -fsSL -H 'Cache-Control: no-cache' \
  https://raw.githubusercontent.com/Kirimbay/docs/cursor/hiddify-block-torrents-0aec/scripts/hiddify-block-torrents.sh \
  -o /tmp/hiddify-block-torrents.sh
grep -m1 '^VERSION=' /tmp/hiddify-block-torrents.sh
sudo bash /tmp/hiddify-block-torrents.sh
hiddify-block-torrents doctor
```

`VERSION` должна быть **1.4.2** или новее. Если `hiddify-block-torrents doctor` отвечает `Unknown command: doctor` — в PATH старая копия. Команды `who` / `status` из неё ничего не чинят: скачайте файл заново и снова запустите `install`.

Снять блок (вернуть как было):

```bash
sudo hiddify-block-torrents uninstall
```

## Что значит «who пустой, doctor неизвестен»

Это не «торрентов нет». Так бывает в двух разных случаях, и их путают:

1. **Старый скрипт.** `who` есть, `doctor` нет. Живой конфиг Xray, скорее всего, ещё без catch-all 1.4. Переустановите 1.4.1.
2. **Утечка на ПК.** После 1.4.1 `doctor` пишет `catch-all: blocked_torrent`, а в qBittorrent DHT всё равно сотни узлов и качает мегабайты. Тогда клиент **не идёт через этот VLESS**. Windows не кормит qBittorrent системным прокси: нужны SOCKS5/TUN того же ключа и «use proxy for peer connections» + DNS через прокси. Пока торрент качается, на сервере:

```bash
ss -uapn | grep -E 'xray|hiddify'
```

`doctor` 1.4.2 сам считает исходящие пиры. `peers: 0` + живой DHT = трафик мимо VPS.

В qBittorrent системный прокси Windows **не** используется. Нужно одно из двух:

1. **Hiddify в режиме TUN/VPN** (не «только системный прокси»), qBittorrent не в split-tunnel exclude.
2. **Прокси в самом клиенте:** Инструменты → Настройки → Соединение → Прокси-сервер, тип **SOCKS5**, `127.0.0.1` и локальный порт Hiddify/v2rayN. Обязательно включить **«Использовать прокси для соединений с пирами»** — по умолчанию она выключена, и тогда DHT/пиры идут в интернет напрямую, даже если «прокси включён».

После этого DHT падает почти до нуля, скорость загрузки → 0.

`who` по гигабайтам **не** ищет торрентщиков. Instagram и YouTube тоже жрут трафик. Смотрите только блок «кого Xray поймал» и `doctor`.

Современный Hiddify хранит пользователей в **MariaDB**, не в `hiddifypanel.db`. Версии до 1.4.1 поэтому писали «нет sqlite-базы». 1.4.1 читает `other/mysql/mysql_pass` и `hiddify-panel/app.cfg`.

## VLESS и остальной VPN

Работают. Скрипт **не трогает входящий VLESS** (Reality, Vision, WS — неважно). Пользователь по-прежнему коннектится на сервер тем же ключом.

Блок срабатывает **уже после расшифровки**, когда Xray смотрит, *куда* человек лезет:

- YouTube, сайты, Telegram, Discord — как раньше, outbound `freedom`;
- BitTorrent / DHT / публичные трекеры — в `blocked_torrent` (это тот же blackhole, только с именем, чтобы потом найти кто это был).

На время установки ядро Xray перезапускается на пару секунд, потом сессии поднимаются сами.

## Как посмотреть, кого поймали

После установки **1.4.1**:

```bash
hiddify-block-torrents doctor
hiddify-block-torrents who
```

- **doctor** — версия в PATH, маркер патча, куда уходит catch-all `0-65535`. Нужно `blocked_torrent`.
- **who** — usage из панели (MariaDB/sqlite, это не торрент) и хиты access-лога с тегом `blocked_torrent` / uuid пользователя.

Вручную: `grep blocked_torrent /opt/hiddify-manager/log/system/xray.access.log`

Дальше в панели этому UUID ставите enable = off. Скрипт сам никого не банит.

## Почему команды хостера не помогли

Поддержка предложила закрыть TCP/UDP **6881–6889** и **6969**. Это классические порты BitTorrent 2004 года. Сейчас клиенты:

- берут **случайный порт**;
- ходят в **DHT** и на **публичные трекеры**;
- часто включают **шифрование протокола**.

Второй момент важнее портов. Hiddify — это **прокси** (Xray / Sing-box), а не классический TUN-VPN. Трафик пользователя расшифровывается на сервере, и уже **процесс xray/sing-box сам открывает исходящие соединения**. Они идут в цепочку **OUTPUT**, не **FORWARD**. Правила только в `FORWARD` хостерский сниппет почти никогда не видит.

Третье: в Xray у Hiddify правило «blackhole для `bittorrent`» уже есть. В **Sing-box** (Hysteria2, TUIC и часть других протоколов) то же правило **закомментировано**. Если люди сидят не на Reality/VLESS, торренты спокойно выходят в интернет.

## Что делает скрипт

1. **Xray** — оставляет штатный blackhole и добавляет блок портов + публичных трекеров / DHT-bootstrap **до** catch-all правила.
2. **Sing-box** — включает рабочий `protocol: bittorrent → reject` (не тот закомментированный кусок с синтаксисом Xray) плюс те же трекеры.
3. **nftables + iptables/ip6tables** — отдельная таблица/цепочка `HIDDIFY_NOTORRENT` на **OUTPUT и FORWARD**:
   - порты 6881–6889, 6969, 51413;
   - handshake `\x13BitTorrent protocol`;
   - DHT (`get_peers`, `announce_peer`, `find_node`);
   - IP публичных трекеров (ipset).
4. **Автоповтор каждые 2 минуты** и сразу после «Apply Configs» / обновления Hiddify, чтобы панель не затёрла правки.

Не используются широкие строки вроде `torrent` или `announce` — они ломают обычные сайты.

С **1.4.0** скрипт больше не полагается только на сигнатуру. Всё, что не веб-порт (80/443 и ещё несколько служебных), через VPN не выпускается. Зашифрованный qBittorrent на случайном порту тоже отваливается. Instagram / YouTube / Telegram / сайты остаются. Могут отвалиться игры и голосовой Discord.

## Честно про лимиты

До 1.4.0 зашифрованный BitTorrent (MSE/PE) без handshake не ловился по сигнатуре. Тогда оставались:

- блок на уровне Xray/Sing-box (sniff);
- трекеры и DHT (без них клиент долго не находит пиров);
- порты по умолчанию.

В 1.4.0 это закрыто allowlist портов. Если после 1.4.2 `doctor` пишет `catch-all: blocked_torrent` и `peers: 0`, а qBittorrent всё ещё качает — включите прокси для пиров или TUN. Это не дыра в фильтре.

## Файлы, которые трогает установка

- `/opt/hiddify-manager/xray/configs/03_routing.json.j2` (+ сгенерированный `.json`)
- `/opt/hiddify-manager/singbox/configs/03_routing.json.j2` (+ `.json`)
- `/opt/hiddify-notorrent/` — копия скрипта и бэкапы
- systemd: `hiddify-notorrent.service` / `.timer` / `.path`

Исходники перед правкой копируются в `/opt/hiddify-notorrent/backups/`. `uninstall` их возвращает.

Перед перезапуском Xray скрипт проверяет, что `freedom` остаётся первым outbound (иначе VLESS лёг бы целиком) и что блок торрентов стоит **до** catch-all. Если проверка не проходит — файлы откатываются, ядро не трогается.

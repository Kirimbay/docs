# Remnawave kit: VLESS + XHTTP + Reality (self-steal), выход через WARP

Набор для развёртывания по состоянию на ноябрь 2026. Что здесь автоматизировано, а что нет, смотри в разделе «Что не проверено».

## Что известно про блокировки (сентябрь - ноябрь 2026)

| Механизм | Признак | Что с этим делать |
|---|---|---|
| Блок IP и целых подсетей/ASN хостера | таймаут на все порты, ping не идёт | другой хостер с «чистым» ASN; новый IP из другой /24; протокол не поможет |
| Выходной IP совпадает с входным | IP банят через часы-дни после начала использования | вход и выход на разных адресах (здесь: выход через WARP) |
| Заморозка ~15-20 КБ | страница начала грузиться и встала, RST нет | XHTTP вместо raw TCP; мало долгих соединений |
| Залп TLS-рукопожатий | больше 3 к одному SNI за доли секунды: заморозка 120 с; смена fingerprint во время заморозки: 600 с | XMUX с явными лимитами; fingerprint не менять на лету |
| TLS fingerprint | uTLS `chrome` (Chrome 133) помечается с октября 2026 | `firefox` |
| Фиксированные «дефолты» XHTTP | `scMinPostsIntervalMs: 30` режут на мобильных | не задавать `scMinPostsIntervalMs` и `scMaxEachPostBytes` |
| Чужой SNI (microsoft.com и т.п.) | SNI не совпадает с владельцем IP | self-steal на своём домене |
| Активное зондирование | сервер не ведёт себя как сайт | реальная заглушка, нормальные заголовки, 404 как у сайта, обычный сертификат (не короткоживущий) |
| Белые списки на мобильном интернете | работает только то, что в списке оператора | протокол не решает; нужен российский ретранслятор в белой подсети |

Источники: [Методичка по построению VPN, осень 2026](https://habr.com/ru/articles/1103460/), [Final Report (октябрь 2026)](https://gist.github.com/nothing-holding/b7f30332411dabbd151abe8184e591fd), [te-st.org №37](https://te-st.org/2026/09/30/vlessmore/), [Вёрстка: волна после выборов](https://verstka.media/posle-vyborov-v-gosdumu-vlasti-nachali-novuyu-volnu-blokirovok-vpn-v-rossii), [net4people #490](https://github.com/net4people/bbs/issues/490), [3x-ui #5141](https://github.com/MHSanaei/3x-ui/issues/5141).

## Схема

```
клиент (Happ/v2rayNG)  --XHTTP+Reality, SNI=свой домен-->  [NODE: вход, TCP 443]  --WireGuard-->  Cloudflare WARP  -->  интернет
                                                              |  Caddy 127.0.0.1:9443 = настоящий сайт-заглушка
[PANEL: отдельный сервер, свой домен, :443 для чужих отдаёт 204]
```

- Панель и нода на разных серверах. IP ноды нигде не светится, кроме хоста подписки.
- Трафик пользователей никогда не выходит через `freedom` с IP ноды: только `EXIT_WARP` или `BLOCK`.
- Хостинг ноды: не Hetzner, DigitalOcean, OVH, Vultr, Contabo. В отчёте за октябрь 2026 проверены AlphaVPS (Нюрнберг) и UpCloud (Хельсинки), у обоих чистые ASN. Проверка делалась только на жёсткий блок IP, не на заморозку 16 КБ, поэтому после покупки проверь сам.
- Пользователей на одной ноде мало (семья и друзья): чем больше, тем заметнее профиль.

## Развёртывание

### 0. Домены
Нужны три A-записи (без прокси Cloudflare, серое облако):
- `panel.<твой домен>` на сервер панели
- `sub.<твой домен>` на сервер панели
- `<нейтральное имя>.<твой домен>` на сервер ноды (например `studio.example.com`; не `vpn`, `proxy`, `node`, `xray`, `reality`)

### 1. Панель (сервер A)
```bash
git clone <этот репозиторий> && cd remnawave-kit/panel
PANEL_DOMAIN=panel.example.com SUB_DOMAIN=sub.example.com bash install-panel.sh
```
Открой `https://panel.example.com`, создай админа. По IP на 443 Caddy отдаёт пустой ответ 204.

### 2. Профиль (любая машина)
```bash
cd remnawave-kit && NODE_DOMAIN=studio.example.com bash scripts/render-profile.sh
```
Скрипт скачает Xray и wgcf, зарегистрирует аккаунт WARP, сгенерирует ключи Reality, shortId и случайный путь, соберёт `out/config-profile.json` и `out/host-values.txt` (там секреты).

В панели: Config Profiles, создать профиль, вставить `out/config-profile.json`.

### 3. Нода (сервер B)
В панели: Nodes, добавить ноду (адрес = IP сервера B, порт 2222, выбрать созданный профиль). Скопируй `SECRET_KEY` из выданного docker-compose.
```bash
cd remnawave-kit/node
NODE_DOMAIN=studio.example.com SECRET_KEY='...' bash install-node.sh
PANEL_IP=<IP сервера A> SSH_PORT=22 ADMIN_IP=<твой IP> bash ../scripts/firewall.sh
NODE_DOMAIN=studio.example.com bash ../scripts/check-node.sh
```
`check-node.sh` проверяет DNS, ответ заглушки и 404, срок жизни сертификата, что порт 9443 только на localhost, версию Xray (нужна 26.10.21 и новее).

### 4. Хост и пользователь (панель)
Hosts, создать хост по значениям из `out/host-values.txt`: адрес и SNI равны `NODE_DOMAIN`, порт 443, **fingerprint `firefox`**, ALPN `h2`, путь из файла. В Advanced, Xray JSON & Raw, xHTTP вставь содержимое `profile/host-xhttp-extra.json` (поле `xhttpExtraParams`). Remnawave в некоторых версиях не передаёт `xhttpSettings` клиенту сам, из-за этого XMUX игнорируется. Проверь, что в клиенте подписки он действительно есть.

Добавь пользователя, привяжи к Internal Squad с этим профилем. Для Happ в ответах подписки задай пароль на локальные SOCKS/HTTP-прокси (`socks-auth-mode`, `http-auth-mode`), иначе приложения на телефоне узнают внешний IP в обход маршрутизации.

### 5. Проверка с клиента (дома и на мобильном)
1. Подключись и держи соединение 2-3 минуты, открывая тяжёлые страницы. Заморозка проявляется не сразу.
2. Открой https://ifconfig.co: должен быть IP Cloudflare, не IP ноды.
3. Если зависло, жди 130 секунд, fingerprint не меняй.
4. Проверь IP ноды из РФ через check-host.net или `hyperion-cs/dpi-checkers`.

## Разбор отказов

| Симптом | Причина | Действие |
|---|---|---|
| На все порты таймаут | блок IP или подсети | запроси у хостера IP из другой /24, либо смени хостера |
| Соединение есть, но через минуту встало | заморозка 16 КБ или залп | убедись, что в клиенте есть xmux (шаг 4), ядро Xray свежее, fingerprint `firefox` |
| Работает дома, не работает на мобильном | оператор или белый список | другой оператор для теста; при белых списках нужен ретранслятор в РФ |
| IP банят через дни | утечка выходного IP | проверь `ifconfig.co`, `check-node.sh`, что в роутинге нет `freedom`, IPv6 выключен |
| Обрывы после обновления панели или ядра | сменились дефолты XMUX | заданы все поля явно, сверь версию в `check-node.sh` |

## Что не проверено

- Я не мог тестировать это из РФ и на реальном DPI. Конфиг профиля и клиентский конфиг прошли `xray -test` (Xray 26.10.31), регистрация WARP и скрипты (`bash -n`) тоже проверены. Установка панели и Caddy в Docker здесь не запускалась: в среде нет Docker.
- WARP как выход: надёжность по российским данным оценивается как низкая. Бесплатный WARP может иметь лимиты на регистрацию, а некоторые сервисы режут его IP. Запасной вариант: свой шлюз на втором VPS (другой хостер) вместо WARP, outbound VLESS+Reality на шлюз с тем же правилом `BLOCK` по умолчанию.
- VLESS Encryption + Vision поверх XHTTP, который рекомендует отчёт за октябрь, здесь не включён: поддержка в панели и клиентах Happ не проверена. Это следующий шаг, когда базовая схема заработает.
- Мобильные белые списки не решены этим набором.
- Законы и правила хостеров о VPN отличаются, оценивай риск сам.

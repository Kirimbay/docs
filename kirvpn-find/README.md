# Панель поиска KirVPN

Веб-панель: поиск пользователя, остаток дней и трафика, число пользователей, оповещение, проверка доступности с российских узлов. На сервере она лежит в `/opt/kirvpn-find` и слушает `127.0.0.1:18765` (снаружи её открывает nginx).

Живые адреса, ключ API Hiddify, ключ SSH, пароль входа, ключ Hostup и тексты оповещений в git не кладутся.

Поиск, расширенный поиск, остаток дней и трафика, число пользователей и ссылки на клиента читают **официальный admin API Hiddify v2**. Root SSH и `mysql` для этого больше не нужны.

Клиент сверен с исходниками [hiddify/HiddifyPanel](https://github.com/hiddify/HiddifyPanel) (ветка `dev`): заголовок `Hiddify-API-Key` — это UUID админа, список пользователей — `GET /api/v2/admin/user/`, домен и путь клиента — `GET /api/v2/admin/all-configs/` и `GET /api/v2/admin/users/`.

## Что прописать на каждый сервер

Файл `nodes.json` лежит рядом с `app.py` и в git не входит. Образец без живых секретов: `nodes.example.json`. Одна запись — один ориджин Hiddify.

Обязательные поля:

| Поле | Пример | Где взять в админке Hiddify |
| --- | --- | --- |
| `label` | `"12"` | Номер сервера, как на вкладках панели. Тот же номер, что в `fleet.json`. |
| `panel_url` | `https://12.kirvpn.us` | Адрес панели **без** секретного пути и **без** UUID. Это хост, который открывается в браузере. В примерах запросов его же показывает раздел **Настройки → API** (классическая админка: Settings → API). |
| `admin_proxy_path` | путь из URL | Секретный путь админки, первый кусок URL после домена: `https://домен/<вот это>/...`. В классической админке: **Настройки → Слишком продвинутые** (Advanced / Too advanced) → **Admin Proxy Path** (`proxy_path_admin`). |
| `api_key` | UUID админа | **Настройки → API**. В заголовок `Hiddify-API-Key` подставляется UUID **админа**, не пользователя. Тот же UUID виден в **Администраторы** у супер-админа и в блоке «Try it» на странице API. Обычный ключ пользователя не подходит. |

Необязательные поля:

| Поле | Зачем |
| --- | --- |
| `ip` | Показывается на карточке. Нужен только для SSH (перезагрузка его не читает отсюда, оповещение по SSH — читает). |
| `announce` | `api` (по умолчанию) или `ssh`. См. ниже. |
| `sub_domain` | Домен ссылки `*.kirvpn.us`, если панель его не отдала в API. |
| `client_proxy_path` | Путь клиента (`proxy_path_client`), если `all-configs` и `users` его не отдали. В админке это **Настройки → Слишком продвинутые → Client Proxy Path**. |
| `timeout` | Секунды на один запрос, от 1 до 60. По умолчанию 12. |

Один мёртвый сервер не роняет страницу: у его карточки будет ошибка, остальные ответят.

Ссылки собираются как раньше:

- клиент: `https://<домен *.kirvpn.us>/<путь клиента>/<uuid пользователя>/`
- админ: `https://<домен>/<admin_proxy_path>/<api_key>/admin/user/`

Домен берётся из API: прямой `*.kirvpn.us` важнее CDN и домена, который годится только для подписки. Если API домен не отдал, используется хост из `panel_url`, когда он тоже на `kirvpn.us`.

## Оповещение

В API Hiddify **нет** метода, который ставит плашку Happ/Incy. В `ConfigEnum` нет ключа announce, шаблон подписки `subscription_header.j2` такой заголовок не пишет.

Ближайшая официальная запись — `PUT /api/v2/admin/settings/` с полем `branding_freetext`. Это текст брендинга на **веб-странице пользователя** (Настройки → Брендинг → свободный текст), не плашка в приложении. Так панель и делает, когда `announce` равен `api` или поля нет.

Плашка в приложении по-прежнему ставится скриптом на сервере: `python3 /opt/kirvpn/set_announce.py`. Это запасной путь по SSH. Чтобы им пользоваться, в записи сервера нужно `"announce": "ssh"`, поле `ip` и файл `id_ed25519`. Без ключа или без IP такая запись вернёт ошибку и остальные серверы не остановит.

## Что ещё ходит не в Hiddify

| Что | Куда ходит | SSH |
| --- | --- | --- |
| Поиск, pro-поиск, счётчик, дни, трафик пользователя, ссылки | Admin API Hiddify | не нужен |
| Оповещение `announce: api` | `PUT .../settings/` (`branding_freetext`) | не нужен |
| Оповещение `announce: ssh` | `set_announce.py` на ориджине | нужен `id_ed25519` и `ip` |
| Проверка подписки из РФ | путь подписки из API Hiddify, затем check-host | не нужен |
| Перезагрузка на вкладке «Тестирование» | `systemctl reboot` по SSH | нужен, см. ниже |
| Трафик машин Hostup | API Hostup, файл `hostup.key` | не нужен. Это расход VPS, не трафик пользователей Hiddify |
| Текст сайта info | локальные файлы панели | не нужен |

Перезагрузка — не функция Hiddify: API не выключает машину. Кнопка работает, только если рядом с кодом лежит `id_ed25519`. Нет файла — ответ «SSH-ключ не задан, перезагрузка выключена», проверка из РФ при этом жива. В `fleet.json` у сервера `"ssh": false` убирает его реле и origin из очереди. Образец: `fleet.example.json`.

`fleet.json` по-прежнему описывает реле, `sub_host` и путь трафика (`rf_direct` или `origin`). Его API Hiddify не заменяет.

## Запуск

Рядом с кодом, не в git: `nodes.json`, `htpasswd`, `session.key`, `fleet.json`. Для трафика Hostup — `hostup.key`. Для скрытых машин — `excluded-ips.txt` (есть пример). `id_ed25519` нужен только если включены перезагрузка или `announce: ssh`.

Проверка клиента API без живых серверов:

```bash
python3 -m unittest test_hiddify_api.py
```

Служба: `kirvpn-find.service`. После правки Python-файлов: `systemctl restart kirvpn-find`.
